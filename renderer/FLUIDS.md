# Vanilla fluid surfaces and waterlogged model composition

Renderer implementation, 2026-11-04. All 119 CPU/OpenGL main Java sources compile with Java 25 and LWJGL 3.4.1. Sixteen native adapters pass syntax parsing only; genuine pinned Windows native API compilation remains pending. No renderer tests, native sampling, GL contexts, pixel comparisons or workflows ran. Unsupported previews remain disabled.

## Capture and ownership

`NativeFluidInputs.capture` supplies vanilla water/flowing-water and lava/flowing-lava geometry for actual native invisible hosts with no block entity. It also supplies fluid layers for successfully selected vanilla JSON bases including reviewed JSON-only entity blocks and offset-dependent models with matching captured native offsets. It reads actual native fluid height, flow, same-fluid relationships, face occlusion shapes, backward top-face visibility, biome water RGB and host light emission. It neither ticks fluids nor changes generation. Original block IDs, full states, biomes, positions and configured height remain in the snapshot and inspection path.

The admitted route is `NativeCapture.weighted` → `NativeCapture.fluids` → the existing `WorldRenderWorker` and `GlWorldView`. The weighted path now has a default dedicated native model RNG factory; explicit-source overloads retain caller policy responsibility. See [MODEL-POLICY.md](MODEL-POLICY.md). `fluids` consumes its owned ready-choice request on success, failure or cancellation after argument admission, retains it through destination admission and requires the same memory coordinator for tracked input. Its result is fully detached. This route does not accept the deterministic `ModelRequest` directly. The generic native visual-edit API remains available.

A borrowed optional neighbor snapshot must belong to the same native source/session epoch and retain the same full vertical interval. Target cells win overlapping lookups. Both palettes are checked against the native registry identities. Native queries use these exact captured states; missing neighbors, unsupported external neighbors or unavailable block entities produce explicit original-state visual problems. No air, clamped boundary, replacement biome or inferred native state is supplied. A surrounding full-height capture can provide horizontal neighbors; uncaptured vertical boundaries remain guarded. Session serialization and source ownership remain the host's responsibility throughout capture.

Already explicit native choices, explicit native layers and empty choices are preserved. Special bases and entity-rendered blocks outside the reviewed JSON-only policy, plus fluid bases missing required native offsets, remain guarded. The default deterministic and weighted APIs still guard fluid-bearing bases; the combined route below is the opt-in producer that can establish both layers together.

## Complete waterlogged scene capture

`NativeCapture.fluidScene` performs volume capture, optional native tint capture, native model/offset/visibility inspection, weighted selections and fluid-layer capture in one admitted native phase. It publishes only the final detached ready-choice request. Both borrowed-catalog and consuming loaded-catalog overloads follow existing session/coordinator ownership. If cancellation, a native fault or admission failure occurs after base preparation, no base-only fluid request is returned. Default capture creates a dedicated source with the reviewed native model factory; explicit-source overloads remain available. Generation RNG state is untouched.

Only this package-internal weighted base phase permits nonempty-fluid native `MODEL` states, and only for known vanilla water/lava with no entity-rendered addition; [reviewed JSON-only entity bases](MODEL-POLICY.md) are allowed. An offset function requires matching successful native-mode offset capture through the existing model guard. JSON resolution, exact original state/properties, native weighted/multipart selections, selected-face coverage and tint coverage still pass through the existing inspector. No dry-state substitution or newly guessed model is used. A failed or unsupported base remains a complete original-state problem even when its fluid could be drawn.

The producer retains each `ModelChoice`'s exact canonical tickets and attaches the fluid mesh as its native layer. Later `WorldVisuals` bakes that JSON base, then combines both layers atomically under the existing geometry/atlas/scene bounds. Block-model tint indices remain on base faces; fluid faces independently carry material RGB with tint index -1. Native fluid faces bypass the block visibility mask, while base faces retain normal cull declarations. State, biome, source cell and picking identity stay those of the original waterlogged block.

Fluid recipes are shared independently from base selections. A composition cache keys the exact base choice and fluid mesh, bounded by the visual choice allowance; different weighted base selections never inherit another base's tickets. The CPU baker additionally shares a base mesh by immutable selected tickets within one exact state/asset plan, avoiding repeated base baking when adjacent cells have different fluid heights/colors. Combined packets remain separate and fully accounted, and all original/scratch/copy and added-packet bounds still apply. No cross-state/archive cache is added.

`fluidScene` now accepts an optional borrowed same-source/full-height neighbor snapshot in both catalog overloads. It validates that receipt before volume/tint/model work, charges its index payload throughout capture, and uses strict native fluid lookups with target cells winning overlaps. The no-neighbor overloads remain available. These neighbors do not extend output volume or replace the baseline block visibility mask. Missing fluid neighbors still produce reported placeholders; no air is inferred at horizontal or vertical boundaries. The existing `fluids` edit route accepts the same optional neighbor contract for already-ready inputs. Existing special/native producers are preserved rather than overwritten.

## Independent model and fluid placement

Each native quad explicitly chooses `BlockMesh.Placement.MODEL` or `CELL`. JSON quads and compatibility constructors use `MODEL`, which adds the captured per-cell native model translation during world emission. Fluid quads, including supplied reverse faces, use `CELL`, which adds only the original cell origin. A waterlogged model can therefore move by its actual native offset without moving the surrounding fluid surface. No offset is subtracted from or baked into fluid coordinates, and no new per-vertex/GPU attribute or offset array is allocated.

Placement follows the face through native intake, ordered composition, packed face metadata and atlas binding. `CELL` faces require explicit native provenance; resource JSON cannot switch placement. Composition preserves every face's policy even across mixed layers. Prototype bounds remain in their unplaced local space; final section bounds are rebuilt from actual emitted vertices after each face's placement. Culling, clipping, camera fit, transparent ordering and triangle/alpha picking use these emitted coordinates and still report the original cell/state/biome. Diagnostic markers remain unit cells at the original origin.

The same fluid recipe and selected base can remain shared across cells with different offsets: placement reads each cell's immutable offset during emission. Nonfinite/out-of-bound native offsets, missing offset capture, special bases, failed model/tint coverage and missing fluid data remain guarded. Native offset behavior is sampled through the existing common API; no offset/random formula or generation behavior is reproduced.

## Geometry and materials

`FluidGeometry.Cell` contains all detached inputs to a fluid prototype: four raw corner heights, visible/overlay face masks, reverse-top flag, flow UV sine/cosine, kind, RGB and emission. Corner averaging, source winding, top/bottom/side insets, rotating top UVs, side UVs and supplied reverse faces follow the reviewed vanilla profile. Horizontal face order is north, east, south, west. Native-selected visible faces have no second block cullface declaration. Every prototype has at most eleven quads.

Shared prototypes require the exact original state index and complete cell recipe within the same source snapshot. Geometry intake retains native provenance and validates every vertex, UV, normal, winding and packet bound. Quad objects are created lazily after count admission. Fully hidden pure-fluid cells become explicit empty choices without requiring sprite assets. A fully hidden fluid layer on a verified model retains the entire selected base. Visible fluids require all sprites of their kind in the selected client archive: water still/flow/overlay or lava still/flow. Missing assets remain reported placeholders.

The new material RGB defaults to white for existing block models. GPU upload multiplies it with an existing block tint if present, using bounded RGB24 channel arithmetic. Fluid faces carry the actual radius-zero native water RGB as material color and tint index -1; lava uses white. No artificial block-model tint layer is reserved. Existing 36/48-byte GPU vertex layouts, atlas animation and picking retain their existing paths. [Fluid material groups](FLUID-MATERIALS.md) now select one alpha class from the complete still/flow/overlay source sheets, shared across every emitted face of the fluid kind.

Simple display lighting uses geometric normals, cardinal shade overrides and the captured emission floor. Explicit final scene RGB remains authoritative through the existing lighting path. Whole-source fluid material union and pass selection are implemented from reviewed source; native execution and pixel comparison remain pending. Native lightmap/AO, UV filtering/shrink behavior and exact pixel parity are not established by source review. Neighbor-biome color blending is not implemented; the policy explicitly records radius zero.

## Bounds and validation

The factory permits 64 Mi native neighbor queries by default, lowerable up to a hard 256 Mi. Existing edit limits bound cells/changes to 16,777,216, new packets to 1,024, added packed geometry to 64 MiB and primitive working allowance to 512 MiB. The effective allowance also respects the original request/visual limits and visibility bytes. Optional neighbor index payload is charged before capture; original input, scratch/final assignment copies (eight additional bytes per cell) and new packed prototypes must fit together. Combined capture includes borrowed neighbor indices in its volume peak and subtracts them from tint/selection working ceilings before allocation. The internal fluid handoff recognizes that parent reservation while still deducting neighbors from the independently configured fluid-edit ceiling; the standalone edit path performs its own full deduction. Reduced request ceilings remain conservative after the borrowed snapshot is released. No neighbor snapshot is retained by the returned request. Geometry and edit admission independently validate output. Palette/reference/object/native overhead still requires combined host admission.
