# Source inventory and editor field policy

Editor coverage and typed reference planning share `editor/tools/iris_source_inventory.py`. It reads the same pinned Iris/VolmLib declarations, source hashes and class fingerprints, including class annotations. Source inventory includes inherited members and all instance-field access levels; static/transient state, enum constants, methods and actual nested declarations are excluded. Field indentation is irrelevant.

The current catalog includes 150 class models, 75 enums and the string-adapted MantleFlag interface across 247 pinned sources. The 149 nonempty class groups contain 1,462 serialized fields. These are the known JSON owner/nested models in the pinned catalog, not a schema for arbitrary runtime extensions or opaque binary assets.

| Policy state | Fields | Meaning |
| --- | ---: | --- |
| Generation with implemented controls | 1,237 | An existing control covers the field in a supported editor context; stored values, ancestors and context limits still apply |
| Read-only | 225 | Metadata, gameplay behavior and schema/compatibility recipes outside direct voxel-generation editing |
| Unclassified | 0 | Every field in the pinned catalog has an audited classification |
| Missing policy entries | 0 | Every inventoried field has a policy entry; unknown pack properties still remain read-only |

`editor/policy/field-policy.json` stores only classifications and reasons. Types, defaults and constraints are not copied into it. Field names and nested type structure come from the shared source inventory; implemented-control coverage comes from the existing UI allowlists. Invalid policy shapes, undeclared fields, unknown groups, source drift and editable allowlist entries without generation classification stop metadata generation. A generation classification by itself cannot mark an unimplemented control as implemented.

The additional reviewed read-only models describe entity spawning/AI/equipment, gameplay effects and commands, item/loot data, block-break drops, marker metadata and post-generation sapling/tree growth. These classifications preserve the existing restrictions on their containing fields. Procedural generation trees use a separate editable model. The 29 previously unresolved modification-recipe fields are now read-only schema/compatibility data, based on a complete pinned production-Java consumer audit. They are not classified as gameplay. The human-readable modification name was already read-only metadata. Generation authoring permissions remain unchanged.

The existing coverage section now derives its class list from the nested source graph, including recursive classes, read-only JSON owners and typed snippet kinds. Cached metadata replaces the former manually maintained per-resource class lists. Coverage remains advisory and does not validate pack contents or authorize edits to read-only resources.

The JSON source browser shows policy information for its selected indexed pointer. It resolves known object fields and canonical array indices, retains restrictions inherited from read-only/unclassified ancestors, distinguishes opaque map members from independently declared Iris fields, and clips generation-model information to read-only resource contexts. Unknown fields, internal metadata-like names, malformed pointers and unsupported structures remain read-only. Snippet contents are not expanded by this browser lookup. Model controls can exist elsewhere without making the selected value editable. Source inspection never reads a pack through the policy API, inserts defaults, changes drafts or triggers generation.

The Windows workflow is prepared to download the complete shared inventory before rebuilding coverage. Deferred contracts cover inherited/shadowed/recursive type graphs, policy shape/source boundaries, honest pending controls, read-only resource and ancestor restrictions, array/map/unknown-pointer handling, and exact source preservation. All 378 Java sources compile; no regression scripts, suites, GitHub workflows or interactive GUI tests ran for this work batch. UI implementation and end-of-UI validation remain unfinished, and unsupported previews remain disabled.


## Modification recipe consumer evidence

The audit covers all 1,778 production Java files under /src/ in Iris revision c3359e0a16438b1bb8468901c6171dcefdf63f7f, excluding test/offline/fixture/benchmark/gameplay source sets. Every file was read and verified against its exact Git blob from the complete, nontruncated pinned tree. [modification-consumer-audit.json](../editor/policy/modification-consumer-audit.json) records the source index, watched recipe types/accessors/property names and observed lexical sites. Comments are excluded; relevant literal names and conservative Unicode escape decoding are included. All eight recipe models contain 30 fields including the already-classified name, so this resolves 29 classifications.

IrisData registers the IrisMod loader and exposes loadAnyMod; the recipe models hold data and IrisMod evaluates compatibility for referenced lists. No production Java recipe-application caller, getter-driven transformation or consumer of the recipe types exists beyond registration and recipe-owned compatibility code. Other forDimension occurrences belong to GenerationHistoryPaths and do not consume recipe data. The audit does not certify external tools, arbitrary reflection or third-party consumers outside the supported native path. It adds no recipe editing, application workflow or generation feature. Shared generation-model children inside a recipe retain their read-only ancestor/resource restrictions. Unknown properties and bytes remain untouched.

The metadata generator now requires all audited recipe groups to remain read-only and binds the evidence to the locked Iris revision. [audit_modification_consumers.py](../editor/tools/audit_modification_consumers.py) can reproduce the complete source audit; the end-of-UI GitHub workflow is prepared to download verified pinned source bytes and run its deferred scope/hash/policy contracts. Source inventory/reasons are not a permission to rewrite selector fields: existing conservative recipe-selector guards remain because no application consumer certifies external transformation semantics. No regression suite or GitHub workflow was executed during this implementation batch.
