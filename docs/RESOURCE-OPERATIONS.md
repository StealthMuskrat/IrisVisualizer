# Closed resource-operation coverage

Rename, same-family move and Delete use a worker-produced review of the frozen in-memory pack. Only a complete, current, permitted report can authorize Apply. Apply updates memory; Save independently preflights writes and baseline-bound old-path removals. Save/Export remain available when a resource operation is blocked.

The current operation schema has ten JSON target families: dimensions, regions, biomes, generators, expressions, image-maps, blocks, structures, jigsaw-pools and jigsaw-pieces. Objects and images can also be mutation targets. Reference ownership additionally covers read-only loot, spawner, entity, marker and modification files, plus 73 source-annotated snippet kinds. These additional families receive no editable field or file-operation authority. The source inventory includes 150 class models, 75 enums and the string-adapted MantleFlag interface: 1,462 direct serialized field declarations bound to 247 pinned Iris/VolmLib source files. The inventory includes inherited members and package/protected/public/private instance fields, excludes static/transient fields, and fails closed on unreviewed declaration or class-annotation changes. Annotation parsing treats comments/literals as source data, so annotation-like text inside descriptions cannot grant authority. It does not establish complete Iris coverage or make every inventoried field editable.

| Reference domain | Planner behavior |
| --- | --- |
| Dimension regions/focus, biome pools/children/carving, generator links | Follow the source-audited loader and complete resource key; maintain incoming and self links |
| Dimension stack and legacy upper dimension | Maintain typed links; preserve inactive `none` and block replacements that would become reserved/inactive sentinels |
| Nested object pools, assembly placements, palettes, replacements and noise styles | Traverse the inventoried object/list graph; maintain typed references without replacing ordinary names, expression code or native registry strings |
| Image-map resource keys | Maintain resource links; named mask binding keys remain ordinary binding identifiers |
| Image-map colors/fallback with one unambiguous BIOME or REGION role | Resolve bare or exact `iris:` keys in that family; preserve surrounding whitespace and the namespace when rewriting |
| Unbound/mixed categorical roles, including categorical plus scalar use | Block affected biome/region operations; never infer the family from the label spelling |
| Surface-block and pure scalar image-map roles | Preserve categorical labels; native surface-block lookup does not use pack block aliases |
| Subterrain exact region allowlists | Maintain canonical keys with region lookups; block noncanonical comparison aliases, alias collapse and new resolution captures |
| Floating carving entry-or-biome strings | Maintain fallback biome links only when source/replacement naming does not collide with the collected dimension/snippet entry IDs; entry identifiers remain unchanged |
| Deposit biome-or-derivative filters | Maintain canonical exact biome keys only when source/replacement derivative identities are unambiguous; preserve namespaced derivative selectors, block alias collapse and newly captured comparisons |
| Local cave-biome allowlists | Maintain complete normalized local keys and case-only aliases; preserve outer whitespace, check the original compatibility lookup separately, and block dotted/unequal aliases or new captures |
| Object collision comparisons | Maintain canonical exact loaded-object keys in allowed/forbidden lists; guard case/dotted/incoming aliases, newly captured names, unsupported spellings and source/destination procedural/ marker namespaces |
| Qualified/unsupported cave selectors | Affected qualified cave lookups and unsafe namespace/Unicode forms remain guarded |
| Read-only loot, spawner, entity, marker and modification owners | Scan certified nested fields; maintain only typed mutable-resource links, leaving item IDs, names, commands, foreign references and NBT data unchanged |
| Modification resource selectors | Nonempty values retain affected-family guards until their comparison semantics are certified |
| Typed snippets in object positions and object-array elements | Follow the class-specific native shorthand rule and exact Windows file path; retain original indirection strings and maintain shared payload reference tokens once |
| Root field-order metadata | Recognize only the exact `Schema.json` path with a complete array of strings; preserve it as nonreference data, and reject other shapes |
| Omitted nested generator/layer/palette/hydrology defaults | Record implicit references; block changes requiring optional settings to be inserted |
| Literal `"null"` in block references | Resolve using the pinned quiet alias loader; preserve/refuse deletion/rename of actual dependencies, and keep JSON null distinct from this string |
| Literal `"null"` in other uncertain lookup modes | Block affected bindings or new captures rather than assuming every native call rejects the key; the audited standard carving fallback retains its known refusal |
| Null/blank biome generator links | Record the runtime `default` generator fallback; never rewrite null/blank values into authored settings |
| Non-null external terrain transformer | Block mutation because provider-defined dependencies cannot be certified from settings |
| State/tile/custom-NBT maps and native-ID maps | Preserve contents; validate the certified container/value shape |

Every frozen eligible owner is parsed before image-map applications and snippet edges are collected. All supported snippet payloads participate even when unused, and a shared payload is scanned only once. The worker checks the snippet graph iteratively: missing/malformed targets, unsafe relative paths, root-string alias chains, cycles, more than 32 links of depth or more than 16,384 snippet occurrences block the operation. The separate typed-resource reference budget remains 16,384. A snippet lookup never uses dotted-prefix fallback; `snippet/short` is resolved under the expected class kind, while a nonmatching prefix after `snippet/` is retained as part of that kind’s relative path. These rules mirror the pinned IrisData adapter and preserve all indirection strings. This makes categorical classification independent of file ordering. Biome-role checks also block a rename that would collapse unequal region-pool aliases into equal strings and change native role inference; unrelated region contexts may conservatively trigger that guard. Exact loader resolution is checked again against the planned path set, including missing references and dotted-prefix aliases, so a new name cannot silently capture an unrelated reference. Rewrites splice only reviewed string-value spans and retain all other source bytes, including large numbers, formatting, unknown opaque map members and untouched assets.

Unknown JSON owners or snippet kinds, unknown model fields (including names that resemble internal schema metadata), invalid snippet positions/shapes, malformed or limited JSON, unsupported reference spellings and exhausted scan budgets block mutations. Root ordering metadata is a narrow shape-specific exception, not a general exemption for arbitrary root JSON. A pack that uses guarded cases can still be edited, saved and exported. These guards do not certify native generation, content validity or preview support.

The model catalog and declaration fingerprints live in `editor/policy/resource-operation-models.json`; exact source hashes and dependency revisions live in `editor/policy/resource-operation-sources.json`. `resource_operation_schema.py` generates the runtime properties from those pinned declarations and explicitly audited reference/default rules. Restricted initializer interpretation handles reviewed constructor/list/palette/style forms and emits family blockers for unfamiliar resource-bearing defaults. It never runs Java or materializes defaults in pack JSON.

The expanded regression cases are prepared but deferred. All 376 editor/test Java sources compile with Java 25. No regression suites, source-drift tests, GitHub workflows or interactive GUI checks have run for this expansion. UI implementation is still in progress; unsupported previews remain disabled and renderer work has not begun.


The pinned Overworld source inventory contains 3,439 JSON files and 504 snippet files. Its observed JSON owner directories and snippet kinds motivated this expansion; complete pack operations, editing coverage, round trips and GUI behavior remain unverified until end-of-UI validation. This inventory is source inspection, not a test execution.


Canonical comparison maintenance is stricter than case-insensitive file lookup. The native subterrain filter compares strings with a region's requested load key. A canonical comparison can follow a rename/move, but an incoming case/dotted alias can collapse previously unequal strings into one new key; that case is blocked. Previously missing comparison names cannot silently start resolving. Other families are not blocked merely by the presence of an unrelated exact region filter.

Carving precedence is collected before any resource references are classified. The pinned dimension getter trims nonblank entry IDs, and the floating-biome resolver looks up the untrimmed carving string with case-sensitive ID matching before falling back to the biome loader. The planner conservatively unions IDs from known dimension entries and typed snippet payloads, including unused payloads. Source/replacement collisions therefore remain guarded even when a narrower runtime context might be safe. Entry names and child-ID strings are never rewritten as biome keys. The context is bounded to 16,384 distinct IDs and 1,000,000 UTF-16 characters; incomplete context never authorizes an operation. This budget applies to affected biome operations and does not obstruct unrelated generator maintenance.

The additional pinned IrisComplex source binds the region-stream callback to `getLoadKey()`. Existing pinned IrisDimension, IrisFloatingChildBiomes, IrisBlockData and ResourceLoader sources bind ID normalization/precedence and the quiet-versus-warning lookup behavior. Deferred contracts cover canonical and alias comparisons, missing-name captures, source/replacement symbolic collisions, typed snippets, lookup-mode uncertainty, ID/character limits and exact persistence. These contracts have been compiled but not executed.


Deposit filters use the pinned native OR comparison: an untrimmed configured string can equal the biome load key, or its implicit `minecraft:` form can equal the logical/vanilla derivative. Derivative values are normalized by native trim/namespace rules, without case folding. The planner collects possible collisions before scanning references, including omitted defaults and the default empty-cave biome constructed by IrisComplex. Explicit null/blank derivatives are preserved. Only the possible source/destination identities are retained (at most two strings), rather than a second unbounded ID catalog. Canonical exact selectors follow rename/move; old/new derivative collisions, noncanonical comparison aliases, loader-alias collapse and newly captured missing names block. Namespaced derivative selectors and non-file spellings retain their exact bytes. A bare derivative selector unrelated to the affected file remains unchanged. Referenced deletion remains blocked. Shared deposit snippets receive the same typed maintenance without changing indirections.

IrisBiomeDerivatives is part of the pinned source manifest (247 sources including the cave-matching consumer chain); its exact Git blob was verified against the locked Iris tree. Its namespace/fallback helpers, the existing IrisBiome getters, IrisDepositGenerator comparison and IrisComplex empty-cave fallback bind this behavior. New Java persistence/comparison cases and Python source-drift cases are prepared and compiled, but have not been executed. The UI stage remains unfinished; affected qualified cave lookups, uncertain collision-marker identities, modification and other unresolved cases retain their guards.


Cave allowlists follow the pinned StructureCaveAnchorResolver implementation rather than its outdated prefix annotation: matching trims ASCII outer whitespace, lowercases with Locale.ROOT and compares complete keys or namespace suffixes; it does not use startsWith. Local reference maintenance preserves case-insensitive matching across known requested load-key aliases. Case-only aliases are safe; dotted/unequal identities block if collapsing them could change a match. The original untrimmed string also participates in IrisStructurePlacement's compatibility-report loader, so its case-sensitive root fallback and missing-name captures are checked independently. Affected qualified rewrites and qualified Windows base-file dependencies remain blocked because that loader domain cannot be certified from comparison identity alone. Unsupported drive-like, compound and Unicode forms retain affected-family guards. Unrelated qualified values, inactive blank/null entries and ordinary text remain untouched. The alias set and per-selector compatibility records stay within the existing complete reference/input budgets, with cancellation checks on the worker.

The source manifest additionally pins StructureCaveAnchorResolver, IrisStructureLocator, Engine and IrisEngine from the locked Iris tree. Their exact Git blobs were verified before recording SHA-256 bindings. These files establish the comparison, its structure-placement caller and native cave-biome lookup routes; they add no serialized models or editing authority. The editor now explains native normalized-name matching rather than advertising partial prefixes. Deferred contracts cover local rename/move, case variants, whitespace/unrelated qualified values, distinct compatibility fallback, dotted aliases/new captures, affected qualified forms, deletion and exact persistence. They have been compiled, not executed. Existing saved-world environments and native generation validity are outside this frozen-pack reference review.


## Object collision load-key comparisons

The pinned placement runner compares the loaded object's getLoadKey() against forbiddenCollisions and allowedCollisions with exact, case-sensitive list membership; allowed membership overrides forbidden membership. The marker decoder and engine preserve the marker object key through the native object loader, which assigns the requested load key. The editor now maintains canonical exact comparison tokens through rename/move, including nested placements in read-only owners and shared typed snippets, without changing list ordering, names, placement options or opaque asset bytes. Exact comparisons protect deletion. Case/dotted aliases, collapse of incoming loader aliases and newly captured missing comparison names remain blocked. Empty/blank lists and values retain their previous inactive behavior. Unsupported spellings keep their affected-family guard; unrelated resource families remain available.

Native marker resolution explicitly excludes the case-sensitive procedural/ prefix. A nonblank collision comparison therefore blocks operations whose source or destination enters that namespace, rather than changing whether a marker participates in collision checks. This conservative rule can block an operation even when its comparison names another object. It describes frozen pack reference maintenance, not migration of previously generated world markers. Three additional sources bind StructurePlacementMarker, PlacedObject and MantleObjectComponent, bringing the shared inventory to 247 pinned sources; they add no serialized models, fields or edit permissions. Deferred drift cases bind the matcher, marker key transport and constructor/loader contracts. Java cases cover canonical/escaped and nested keys, shared snippets, read-only ownership, alias/new-capture/procedural guards, deletion and exact Save/Copy/As/ZIP. These cases were compiled, not executed; unsupported previews remain disabled.
