## Explicit boundaries

- Original dimension region/exclusion string arrays, region biome pools, biome child links and biome-generator links now render at most 200 editable rows per page, using full-list indices for every operation. Page navigation retains off-page drafts and the new-entry form; clean row input buffers outside the visible page are released, while pending text remains retained explicitly. Counts show pending cells on other pages, and existing full-list structural draft guards continue to see them. Only successful add/duplicate/move/remove actions select the resulting global row and request one scroll reveal; failure or declined draft disposal does not move the page. Per-list positions are isolated within one selected resource, and workspace/path/empty-selection changes release them even when no list UI is drawn. Ordinary scalar edits and Save/Copy/As/ZIP retain presentation state; smaller counts clamp only the page. No list is truncated or rewritten by paging, and source parsing/1 MB inspector limits remain unchanged; this bounds rendered rows and clean buffers rather than claiming asynchronous or partial JSON parsing. NUL-containing string entries now join oversized entries as text read-only, avoiding an unfaithful native buffer/phantom draft while retaining existing explicit removal and source bytes. No authoring, reference, default, preview or storage permission is added. Native interaction and responsiveness still require end-of-UI validation.
- Asset import, replacement and batch capture, image statistics, pending-destination review, folder copy and ZIP export now turn worker memory errors into explicit terminal failures instead of leaving a dead worker and permanent busy state. They wait for an explicit retry and retain existing one-active/latest-pending or one-job semantics. Work runs in a returning execution frame and parked loops clear old job/outcome locals; reviewed resource addition uses the same release boundary so cleared prepared payloads are not retained by idle stack slots. Copy/ZIP/disk-review queue state is committed only after snapshot setup succeeds, and memory failures during setup are reported through existing UI error handling. Save As capture failures retain its active folder/baseline. Copy/export error diagnostics remember that publication started even after the publication control reached DONE, report destination inspection when appropriate, and never issue a false success receipt. A failed Save As cannot adopt that destination; normal explicit retry uses a new reviewed snapshot. Existing staging cleanup, budgets, cancellation boundaries, storage conflict checks, workspace/draft ownership and preview availability are unchanged. Source review confirms the release boundaries; actual heap/GUI behavior remains untested.
- Supported original scalar controls now offer Use Iris default for dimension, region, biome and generator fields, nested noise/fracture fields, numeric styles and terrain profiles. This explicitly removes one stored override, using pinned default metadata for the explanation, and keeps existing parent objects and unknown siblings. It never inserts the default value, prunes parents, removes arrays, changes base-style enums or resets a whole resource. Absent fields remain absent; wrong stored shapes/native widths and unsupported contexts retain read-only guards. Type-valid numeric bound errors can be explicitly reset. Style reset reuses existing context bounds and cellular consistency checks. Paired biome-generator height reset removes both supported endpoints atomically and preserves the generator reference and other link data. Successful actions clear only their exact draft cells; unrelated and similarly prefixed rows retain drafts, and failures clear none. Save/Export and existing in-memory Undo/Redo retain normal behavior. No engine action, field-policy change or new generation support follows from these controls; interactive confirmation of the controls remains pending.
- The original dimension/region/biome/generator numeric controls, nested noise/fracture fields, style controls, terrain profiles and paired biome-generator heights now validate raw JSON-number drafts before any double conversion. The shared helper reads existing pinned native types, bounds and options; it adds no schema/default/policy copy. Exact int32/int64 widths and decimal bounds/options reject values that only look valid after rounding, and Java-only hex/suffix/plus spellings, overflow and nonzero input underflow are rejected. Accepted exponent/trailing-zero/signed-zero spellings splice only their selected numeric token; absent fields still require Enable. Stored wrong native shapes/widths, nonfinite doubles and tokens over the explicit 4,096-character numeric budget stay read-only, while type-valid values outside bounds remain correctable. Inspection preserves stored native double underflow rather than normalizing it. Existing double-taking APIs keep their prior canonical spelling for compatibility; UI text never uses them. Height-pair Apply/Add validates both exact values and ordering before producing bytes, and enables absent members only on explicit paired Apply. Existing context-specific style/cellular constraints, scopes, drafts, reference rules and Save/Export behavior remain in force. No generation is run and no additional field gains authoring authority.
- Preview tabs synchronize with ImGui through a pending request rather than reasserting the old session mode every frame. New resources, workspace replacement, explicit mode changes and responsive table-scope changes request their meaningful current/default mode once; old native content is ignored until acknowledgement, and ordinary user switches stay native. Both tabs remain visible with inapplicable modes disabled. Source inspection of the pinned ImGui 1.92.7 tab implementation confirmed deferred selection is the relevant contract; native mouse/keyboard interaction remains untested. Image capture, decode and upload memory failures now produce explicit retryable errors. Invalid/null captures and changed source stamps cannot enqueue a decoder. End-of-frame metadata polling drops obsolete pending/decoded image work after navigation, applied edits, Undo or workspace replacement without reading image bytes or starting another decode. An existing codec may finish, but cannot publish stale output; one active/latest pending behavior remains. Waiting workers release obsolete raster references. Only a meaningful image view schedules image decoding, so unsupported paths cannot trigger hidden loads. GPU image setup checks the texture name and both allocated dimensions; upload cleanup and visible failure remain within the existing read-only image path. Save/Export and native generation availability are unaffected.
- Browser F2/Delete target the focused hierarchy row only, with exact unmodified keys and guards for active editors, popups and pointer ownership. Search, filters, pagers and old resource selections cannot dispatch them. Menu / Shift+F10 and plain right-click open the same row actions, including existing reviewed create/duplicate routes and disabled unsupported operations. Enter/keypad Enter toggles a folder; forced-open searches remain expanded. Ctrl-left file duplication, Ctrl-right folder creation and Ctrl-middle subfolder creation reject extra Shift/Alt/AltGr/Super modifiers; keyboard Ctrl+Enter never duplicates. File and folder highlighting no longer compete, revealing a file clears obsolete folder selection, and hierarchy indentation shares the session scale. No operation gains authority, bypasses draft/reference/history guards or changes storage behavior. Native GUI interaction still needs end-of-stage verification.
