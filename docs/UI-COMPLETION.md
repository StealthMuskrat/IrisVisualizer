## Explicit boundaries

- Browser F2/Delete target the focused hierarchy row only, with exact unmodified keys and guards for active editors, popups and pointer ownership. Search, filters, pagers and old resource selections cannot dispatch them. Menu / Shift+F10 and plain right-click open the same row actions, including existing reviewed create/duplicate routes and disabled unsupported operations. Enter/keypad Enter toggles a folder; forced-open searches remain expanded. Ctrl-left file duplication, Ctrl-right folder creation and Ctrl-middle subfolder creation reject extra Shift/Alt/AltGr/Super modifiers; keyboard Ctrl+Enter never duplicates. File and folder highlighting no longer compete, revealing a file clears obsolete folder selection, and hierarchy indentation shares the session scale. No operation gains authority, bypasses draft/reference/history guards or changes storage behavior. Native GUI interaction still needs end-of-stage verification.
- Panel widths, divider gestures and F6/Shift+F6 focus routes are editor-session state only. Normal-width panels retain usable minimum widths; smaller windows scale those minima without overwriting preferred proportions. Drag either boundary, double-click to reset, or use Workspace > Layout for keyboard-accessible width and focus commands. The preview toolbar switches between a single row, a compact two-row layout and a stacked layout; image buttons and coordinate inputs wrap to fit. Original image pan/zoom, exact preview coordinates, disabled generation/auto controls and all five File actions remain in place. Native zero-sized windows use a clipped one-unit size rather than triggering automatic window sizing. These changes still require interactive validation.
- Display scale follows the GLFW Windows content scale by default, with session-only absolute 100/125/150/175/200 percent overrides under Workspace > Layout > Display scale. Invalid monitor samples retain the last usable value, and samples are quantized to individual DPI steps to avoid font churn. Choices apply between UI frames. Native ImGui DPI fonts and owned spacing metrics use absolute base values, avoiding repeated style-multiplication drift; framebuffer dimensions remain owned by the existing backend. Shell minima/default widths, divider hit targets and keyboard steps, preview toolbar columns/breakpoints/inputs and initial review-window sizes share the scale. Preferred panel proportions survive temporary scale compression; reset widths does not reset display choice. Existing auxiliary window geometry is retained after opening. Focus and height details now open keyboard-navigable popups as well as supporting hover help. These changes touch no pack data, drafts, engine settings or renderer behavior and still require Windows interactive validation.
- Preview choices are UI state. They do not modify pack JSON, create temporary pack overrides, select a replacement engine, or authorize native preview output.
- Selected dimension height metadata is read from immutable applied bytes on a bounded background worker, with one active read and one replaceable pending source. Unchanged frames, unrelated edits and Save do not reparse it; changed/removed paths, content revisions, workspace replacement and hidden-panel polling discard stale output. Absent dimensionHeight uses pinned dimension defaults; a present partial range uses pinned range-member defaults, with provenance in the height tooltip. Exact integer endpoints and the complete span are shown without truncation, with existing native bound/alignment/logical-height constraints reported separately. Explicit null, malformed/unsupported JSON, fractional endpoints and files exceeding 1 MB remain unresolved, with no substituted height. Oversize sources retain only their size. Stable failures wait for an edit or explicit retry. This reads no dependencies, validates no borrowed dimension-type registry and claims no native generation readiness; it never blocks Save/Export or includes pending Inspector drafts.
- Biome and region Placement choices distinguish selected-resource isolation from the dimension's stored settings. Isolated request descriptors identify the exact resource type/key and dimension, clear the competing focus field, and retain the current seed/location/framing. Dimension settings emits no focus overrides and does not promise the selected resource occurs naturally: stored pack focus remains in force. Source-bound guidance explains biome LAND role, native region resolution/synthesis, version exclusions/unloadable focus and studio-buffet precedence. The UI never synthesizes a region or runs native selection itself. Choices survive navigation, mode/context changes and applied resource rename/move; deletion, path reuse and pack replacement discard old choices. Descriptors are immutable, separate UI metadata only; native installation/validation remains unavailable. No additional pack editing authority or dependency guarantee follows from them.
- Area / scale keeps 512 × 512 map samples at configurable positive finite blocks per sample (default 1), and positive integer 3D width/depth (default 128 × 128) over the full configured height. X/Z identify the first sample/block. Framing applies independently per mode and dimension without discarding unrelated pending location or other-mode framing input. Applied settings follow an applied dimension rename and disappear with deletion or workspace replacement. Image, object and structure views do not expose terrain framing. Requests outside signed 32-bit coordinate endpoints report errors without clipping or blocking Save/Export. This is UI request metadata only: it allocates no output and certifies no native budget, world validity or generation readiness. Exact resource family/key/path metadata distinguishes grouped structure types and image extensions without granting generation authority.
- Partial reference reports never authorize rename/move/delete. The closed source-bound schema now covers dimensions, regions, biomes, structures, pools, pieces, generators, expressions, image-maps and blocks, with 150 class models, 75 enums and the string-adapted MantleFlag interface. Five additional read-only owner families (loot, spawners, entities, markers and mods) and 73 annotated snippet kinds participate in reference scanning without gaining field/file-operation editing authority. Only the exact root Schema.json string-array ordering format is recognized as nonreference metadata. Objects/images are supported targets. Unrecognized JSON owners, unknown fields, unsupported shapes, malformed/limited JSON and exceeded budgets block operations. The lexical inventory includes package-private fields and inherited declarations, and rejects ambiguous initialization/field forms. It is not a complete Iris schema or a grant of additional editable controls.
- Typed links include dimension region/focus/stack links, biome pools/children/carving/generators, nested object/structure/material/noise references and unambiguous categorical image-map biome/region targets. Binding resource keys are distinct from named mask binding keys. Namespaced vanilla states, state/tile/NBT maps and native surface-block labels are preserved. Omitted generator/palette/layer/hydrology defaults and null/blank generator fallbacks participate without inserting settings; affected operations block. Legacy none sentinels remain inactive, and replacements cannot acquire sentinel meaning. Canonical exact region and unambiguous deposit biome filters now follow file operations while alias collapse, derivative collisions and new comparison captures are blocked. Unambiguous floating carving fallback links are maintained after collecting native entry-ID precedence; source/replacement ID collisions stay guarded. Quiet block aliases support the literal string null, while uncertain affected reserved-name bindings block. Normalized cave allowlists now follow native trim/case matching with separate compatibility-loader checks; qualified suffixes rejected by the raw case-sensitive biomes: folder filter also follow unambiguous rename/move. Literal biomes: rewrites, dotted/unequal aliases and new captures block. Mixed/unbound categorical uses, affected literal biomes: cave lookups, ambiguous deposit identities, uncertain collision-marker identities and modification selectors retain their guards. Typed snippet indirection strings retain their original bytes; shared payload references are scanned and rewritten once. Missing, unknown-kind, invalid-shape, unsafe-path, cyclic, over-depth or over-budget snippet dependencies block mutation. See [resource-operation coverage](RESOURCE-OPERATIONS.md) for the exact boundaries.
- Field coverage is source metadata. Its generated nested/inherited type graph now covers all class models in the shared catalog, including read-only owners and typed snippets. The JSON source browser resolves declared array/object paths, inherits containing-field restrictions and keeps map members/unknown data read-only. No metadata classification authorizes writes, enables an unsupported context or validates native generation. The 29 previously unclassified modification-recipe fields are now audited read-only schema/compatibility data. A separate complete 1,778-file pinned production-Java audit found registration/loading and recipe-owned compatibility reporting, with no recipe-application consumer. All 30 recipe fields, including the already-classified name, retain read-only authority; external consumers are not certified. The shared serialized model catalog remains 247 pinned sources.
- Small numeric ranges now use integer or double-precision sliders alongside exact text entry, using the same metadata and context-specific bounds as existing validators. Finite ranges spanning at most 1,024 units qualify; wide, unbounded, unusably tiny, unknown-type and signed64 fields keep text entry. Pinned discrete numeric choices use a slider through source-ordered options, with exact entry and an explicit allowed-choice picker for unsupported drafts; no intermediate or approximate numeric options are invented. Bounds-only contracts get an explicit native type from their owning helper. General palettes retain 1–1,000 weights while fluid/material palettes retain 1–64. Existing workcell drafts no longer undergo integer parsing merely to draw the next frame; incomplete values stay correctable. Structure limits now share pending drafts and explicit Apply/reset handling. Slider changes update drafts only; existing explicit Apply and atomic paired setters remain authoritative. Drawing a field never rewrites its token, inserts an omitted default or clamps an invalid/out-of-range/inherited draft. Existing enable/reset/null controls and Save behavior remain unchanged. This presentation layer does not add editable fields or native evaluation.
- Object collision lists now follow native exact loaded-key comparisons. Canonical keys update with rename/move across normal/floating placements, shared snippets and read-only owners; allowed/forbidden precedence and list order remain intact. Case/dotted aliases, incoming alias collapse, new missing-name captures and unsupported spellings stay guarded. Nonblank collision settings conservatively block operations touching the native reserved procedural/ marker namespace. Object bytes are never decoded or edited, and no saved-world marker migration or native generation validity is claimed.
- Resource Apply changes only memory. Save preflights all planned writes/removals, publishes destinations and reference rewrites, then removes baseline/identity-bound old regular files without recursive deletion. Partial-save progress remains explicit and retryable. Pending removal state retains hashes, never old file bytes. Save Copy/As/ZIP use the current graph; fresh-folder adoption leaves the former folder intact.
- Full rendered preview output, camera/mesh/model/texture rendering, fidelity checks and engine-output rendering comparison belong to the renderer stage after UI completion.
- No backup, autosave recovery, crash recovery or disk file-history feature is authorized.
