# Real Overworld native structure planning

This development proof exercises the official structure-start and reference stages with the pinned, unchanged Overworld pack at seed 1337. It is not a complete world-generation or independent parity result. Structure blocks, native features, terrain and meshes are not generated by this probe.

## Run

On Windows x64 with Java 25:

```powershell
./scripts/Prepare-Sources.ps1
./scripts/Test-OverworldContext.ps1 -StructurePlanning
```

Output is written once under `build/overworld-structures/`. The existing context-only audit remains available without the switch. Both audits keep `previewAllowed=false` and all four readiness blockers.

The structure proof opens the official native terrain context with `minecraft:overworld` as its level key and noise settings. The explicit developer fixture at `native-feasibility/src/test/resources/spigot-structure-context.yml` requests native Spigot structure defaults; its SHA-256 is recorded. These are test inputs, not defaults inferred for a user pack or future application session.

## Checks

- Find eligible ancient-city starts in bounded negative and positive quadrants through the official placement planner, retaining the pack's spacing, source, height and terrain settings.
- Generate native pieces using the official headless structure planner and verify configured ownership fingerprints.
- Compare each city's complete start NBT against a direct call to the official native structure factory with identical inputs. This isolates orchestration errors; it is not an independent complete-world baseline.
- Plan the full radius-eight origin halo (289 chunks) around the negative start. Reject a missing corner before accepting the complete grid, then require the city's origin reference and the correct structure-reference status.
- Record all valid starts and piece counts in `structure-starts.tsv`, including any natural starts discovered by the official planner.
- Close the native context and engine, verify no history router or history directory, preserve source bytes, and delete disposable generation data.

The full terrain height stays unchanged. The earlier 96 MiB index allocation remains a separate check, with buffers released before structure planning. Total generation/native/mesh memory is still unconfirmed.

## Verification status

Windows integration verification is pending for this batch. Passing this probe will establish only native start planning, ownership and references. Native piece block placement, complete placed-feature execution, an independent backend comparison and total memory validation remain required before faithful full-world previews.
